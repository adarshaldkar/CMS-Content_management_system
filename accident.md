# Editorial Data Protection & Failure Recovery Architecture (`accident.md`)

> **Document Status**: Production Architecture Specification  
> **Classification**: Core Editorial Resilience Standard (P0 Invariant)  
> **Objective**: Eliminate all forms of manuscript data loss across accidental browser navigation, tab closures, browser crashes, network dropouts, multi-tab editing collisions, and concurrency conflicts.

---

## 1. Multi-Tier Persistence Topology

In The Gazette Editorial Studio, manuscript state flows across **three distinct, non-competing storage tiers**:

```text
                               AUTHOR TYPES IN EDITOR
                                         │
          ┌──────────────────────────────┼──────────────────────────────┐
          ▼                              ▼                              ▼
  Tier 1: In-Memory DOM          Tier 2: Local Recovery        Tier 3: Cloud Database
  (React + TipTap JSON)               (IndexedDB)                 (PostgreSQL / API)
  • Instant rendering            • Debounced (1,000ms)         • Debounced (1,500ms)
  • 0ms input latency            • Crash/Offline backup        • Authoritative single source
  • Ephemeral (wiped on unmount) • Survives browser restart    • Revision & workflow ledger
```

| Tier | Role | Storage Medium | Latency / Frequency | Authority |
|---|---|---|---|---|
| **Tier 1 (Transient)** | Immediate typing & UI responsiveness | React State / TipTap DOM | 0ms (instant) | Local presentation only |
| **Tier 2 (Recovery)** | Disaster backup & offline continuity | Browser IndexedDB | 1,000ms debounce | Local rescue fallback |
| **Tier 3 (Authoritative)** | Multi-device truth & revision history | Server PostgreSQL / MongoDB | 1,500ms debounce | **Absolute canonical authority** |

## 2. Debounced Local Recovery via IndexedDB

### 2.1 The IndexedDB Schema
Instead of relying on the restrictive 5MB synchronous `localStorage` (which blocks the main thread and throws `QuotaExceededError` on large documents with tables/images), Gazette uses an asynchronous **IndexedDB Object Store** (`gazette_editorial_recovery`):

```typescript
export interface LocalDraftSnapshot {
  articleId: string;              // Article UUID or 'new'
  baseVersion: number;            // Server version this draft was branched from
  seq: number;                    // Client monotonic sequence number
  title: string;
  slug: string;
  description: string;
  content: string;                // Full HTML / TipTap JSON tree
  categoryId: string;
  tags: string[];
  coverImage: string | null;
  seoTitle?: string;
  seoDescription?: string;
  wordCount: number;
  readingTimeMinutes: number;
  savedAt: string;                // ISO timestamp of client snapshot
  checksum: string;               // SHA-256 hash of content payload
}
```

### 2.2 Debounce & Throttle Rules
* **No Raw Keystroke Writes**: Keystrokes are buffered. A snapshot is dispatched to IndexedDB **1,000ms after typing halts**, or at a maximum throttle interval of **5,000ms during continuous typing**.
* **Zero UI Thread Blocking**: All database operations execute asynchronously via IndexedDB Promises.
* **Storage Eviction**: Local snapshots are automatically purged once the server returns HTTP 200 acknowledging a durable database save.

## 3. Authoritative Server Autosave & Dual-Key Concurrency Control

### 3.1 The Dual-Key Save Envelope
Every autosave HTTP payload sent to the backend includes two concurrency keys:
1. `baseVersion`: The exact version of the story the editor opened (`v18`).
2. `seq`: A monotonically increasing integer generated by the client (`seq: 42`).

```json
{
  "articleId": "art_9918a2",
  "baseVersion": 18,
  "seq": 42,
  "title": "Global Semiconductor Trade Shifts",
  "content": "<p>Updated analysis...</p>",
  "expectedVersion": 18
}
```

### 3.2 Server-Side Concurrency Validation:
```text
Client submits payload with (baseVersion: 18, seq: 42)
                    │
                    ▼
Does Current Server Version == baseVersion (18)?
       │
       ├──► YES: Increment version to 19 → Persist to DB → Return { success: true, version: 19, seq: 42 }
       │
       └──► NO (Server is already 19 or 20):
             Return 409 CONFLICT: { currentVersion: 19, updatedBy: "Jane Editor", updatedAt: "..." }
             Trigger Conflict Resolution Studio on Client
```

## 5. Navigation, Refresh & Tab-Close Protection

### 5.1 Triple-Barrier Navigation Defense

```text
                               AUTHOR ATTEMPTS TO LEAVE
                                          │
        ┌─────────────────────────────────┼─────────────────────────────────┐
        ▼                                 ▼                                 ▼
1. Browser Back / Popstate        2. Hard Refresh / Tab Close       3. In-App Navigation
• Trapped via popstate listener   • Trapped via beforeunload        • Trapped by React Router Guard
• Re-pushes guard state           • Browser native confirmation     • Displays Gazette Modal
• Opens Unsaved Changes Modal     • Prevents tab termination        • "Save & Exit" / "Discard"
```

### 5.2 The "Save & Exit" Deterministic Workflow
Instead of forcing authors to navigate backward, the top header features an explicit **"Save & Exit"** action:
1. Immediately cancels pending debounce timers.
2. Flushes the active manuscript state to the server API.
3. Awaits the HTTP 200 confirmation response.
4. Clears local IndexedDB recovery cache for this story.
5. Safely transitions the browser route to `/stories`.

## 6. Multi-Tab Detection via BroadcastChannel

When an author opens the same story across multiple tabs or browser windows:

```text
  TAB A (Active Editor)                      TAB B (Duplicate Session)
          │                                              │
          │────── BroadcastChannel('gazette_tabs') ─────►│
          │       "CLAIM_EXCLUSIVE_EDIT: art_9918a2"     │
          │                                              ▼
          │                                ┌───────────────────────────┐
          │                                │ ⚠️ CONCURRENT TAB DETECTED│
          │                                │ Story is active in Tab A. │
          │                                │ [ Take Over ] [ View Only ]│
          │                                └───────────────────────────┘
```

1. **BroadcastChannel Signaling**: Detects duplicate local sessions in real-time across tabs of the same browser profile.
2. **Server Concurrency Safeguard**: Even if `BroadcastChannel` is bypassed (e.g. separate browser or machine), the server's `baseVersion` optimistic check stops silent overwrites.

## 9. Destructive Action Safety & Revision Guarantees

1. **Append-Only Revisions**: Rolling back or restoring an earlier version never deletes the current version. A new revision `v(N+1)` is created, preserving complete editorial lineage.
2. **Catastrophic Selection Overwrite Protection**: If word count drops by >60% in a single edit operation (e.g. accidental `Ctrl+A` + Backspace), a transient undo snapshot is locked in IndexedDB to allow one-click emergency restoration.
3. **Background Media Upload Continuity**: Media uploads and PDF parsing tasks communicate with background service workers or BullMQ queues; leaving or switching tabs does not abort server-side ingestion.

## 10. Summary Matrix of Handled Edge Cases

| Failure Scenario | Primary Defense | Recovery Mechanism | Result |
|---|---|---|---|
| **Accidental Browser Back** | `popstate` history trap | Unsaved Changes Modal + "Save & Exit" | Navigation blocked until confirmed |
| **Accidental Refresh (`F5`)** | `beforeunload` native prompt | IndexedDB snapshot | Prompt shown; 0 data loss |
| **Tab / Window Force Close** | `beforeunload` event | Local IndexedDB snapshot | Draft restored on next visit |
| **Browser Crash / Power Loss** | Debounced IndexedDB engine | Reconciliation Banner on mount | Full manuscript recovered |
| **Network Dropout while typing** | Offline State Machine | Local queue + auto-sync on reconnect | Status shows "Offline — Saved locally" |
| **Concurrent Multi-Editor Save** | `baseVersion` optimistic check | 409 Conflict Resolution Studio | No silent overwrites; visual diff |
| **Multi-Tab Collision** | `BroadcastChannel` coordination | Takeover modal | Prevents split-brain typing |
| **Editing Live Published Story** | Staged Draft Forking | Live v18 preserved; v19 staged | Zero accidental production changes |
| **Accidental "Select All" Delete** | Heuristic drop threshold | IndexedDB undo anchor | Emergency one-click undo |
